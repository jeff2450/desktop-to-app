# WebToApp Pipeline — Suggested Improvements

Based on a full read of all pipeline stages, here are concrete improvements grouped by effort.

---

## 🟢 Quick Wins — Low effort, high impact

### 1. Pre-flight Validation (Stage 00)

**Problem:** The pipeline fails silently mid-way when the source project is misconfigured.  
**Fix:** Add a Stage 00 that validates the source before any work starts:

```typescript
// packages/core/src/pipeline/stages/00-preflight.ts
const checks = [
  { name: "package.json exists",   pass: await fileExists('package.json') },
  { name: "src/ directory exists", pass: await fileExists('src/') },
  { name: "index.html exists",     pass: await fileExists('index.html') },
  { name: "vite config exists",    pass: await fileExists('vite.config.ts') || ... },
  { name: "not a Next.js project", pass: !deps['next'] },  // warn, not block
];
// Fail fast with a clear message before touching anything
```

---

### 2. Expand the Orphaned Import Scrubber (Stage 03)

**Problem:** The current scrubber only handles 5 hardcoded modules. Any Lovable project
can have additional cloud-specific files that get deleted (e.g. `src/lib/supabase.ts`,
`src/integrations/supabase/client.ts`, `src/contexts/AuthContext.tsx`).  

**Fix:** Make the scrubber **dynamic** — derive the list of patterns to scrub from
`plan.filesToDelete` instead of a static list:

```typescript
// In 03-transform.ts — build patterns from the deletion plan
const deletedModuleNames = plan.filesToDelete.map(f =>
  path.basename(f, path.extname(f))   // "syncEngine", "supabaseClient", etc.
);
// Then scrub imports containing any of those module names
```

---

### 3. Fix the SQLite Schema — Use Real Column Types

**Problem:** The current SQLite table generator uses a single `data TEXT` column for everything:
```sql
CREATE TABLE IF NOT EXISTS medications (
  id   TEXT PRIMARY KEY,
  data TEXT NOT NULL DEFAULT '{}'  -- ❌ all data in one JSON blob!
)
```
**Fix:** Read the Supabase `types.ts` that Stage 01 already parses, and extract per-column
types to generate proper schemas:

```sql
CREATE TABLE IF NOT EXISTS medications (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  dosage      TEXT,
  created_at  TEXT DEFAULT (datetime('now'))
)
```
This means the frontend's existing queries (`select * from medications where name = ?`)
work correctly instead of requiring JSON parsing.

---

### 4. Environment Variable Cleanup

**Problem:** The source `.env` has Supabase/Firebase cloud keys that land in the output
project unchanged. They don't cause build failures but expose cloud credentials in a
local desktop app unnecessarily.

**Fix:** In Stage 04/05, generate a clean `.env` for the output project:

```bash
# Generated by WebToApp
VITE_LOCAL_API=true
VITE_API_PORT=3001

# Original cloud keys — kept for reference, not used in offline mode
# VITE_SUPABASE_URL=https://xxx.supabase.co
# VITE_SUPABASE_ANON_KEY=eyJ...
```

---

### 5. Icon Auto-Detection

**Problem:** `electron-builder.yml` always defaults to `assets/icon.png` which rarely exists,
causing the installer to use a blank icon.

**Fix:** Stage 01 can detect common icon locations and Stage 04 copies + sets the correct path:

```typescript
const iconCandidates = [
  'public/favicon.ico', 'public/logo.png', 'public/icon.png',
  'src/assets/logo.png', 'assets/icon.png'
];
// Copy the first found icon → assets/icon.png, set in electron-builder config
```

---

### 6. Add `--dry-run` Mode

**Problem:** Users can't preview what the pipeline would do before committing.

**Fix:** Accept a `dryRun: true` config option — log every planned action but skip
all file writes and npm installs:

```
[DRY RUN] Would delete: src/lib/syncEngine.ts
[DRY RUN] Would scrub imports in: src/components/SyncStatus.tsx
[DRY RUN] Would generate: electron/main.js
[DRY RUN] Would add to devDependencies: electron@^31.0.0
[DRY RUN] Would run: npm install --legacy-peer-deps
```

---

### 7. Stage-Level Resume (Retry from Stage N)

**Problem:** If Stage 06 (Vite build) fails, users have to re-run the entire 5-minute
pipeline from Stage 01 even though Stages 01–05 already succeeded.

**Fix:** Write a `webtoapp-state.json` after each successful stage:

```json
{ "lastSuccessfulStage": "05-install", "outputDir": "...", "timestamp": "..." }
```

On retry, skip completed stages and resume from the next one.

## 🟡 Medium Effort — New capabilities

### 8. AST-Based Import Scrubbing (Replace Regex)

**Problem:** The current regex-based orphaned import scrubber can break valid code in
edge cases (e.g. multi-line imports, string literals that happen to match, commented-out
imports being removed).

**Fix:** Use `@babel/parser` + `@babel/traverse` or the TypeScript compiler API for
reliable, AST-level import removal:

```typescript
import { parse } from '@babel/parser';
import traverse from '@babel/traverse';
// Safely remove only the exact import node, regenerate file with @babel/generator
```

---

### 9. Supabase RLS → Express Middleware Auto-Migration

**Problem:** Supabase Row Level Security policies are silently dropped. The generated
Express routes expose all data to all users.

**Fix:** Parse Supabase migration SQL for `CREATE POLICY` statements and generate
corresponding `requireAuth` middleware on the Express routes:

```javascript
// Generated from: CREATE POLICY "Users can only see own data" ON medications
//                 USING (auth.uid() = user_id);
router.get('/', requireAuth, (req, res) => {
  const rows = db.prepare(
    'SELECT * FROM medications WHERE user_id = ?'
  ).all(req.user.id);  // auto-generated from policy analysis
  res.json({ data: rows });
});
```

---

### 10. Vite Config Regeneration (Replace Regex Patching)

**Problem:** The current approach of regex-patching the source `vite.config.ts` is
fragile — it can't handle every possible plugin configuration and can produce
syntactically broken config files.

**Fix:** Instead of patching, **generate a clean `vite.config.ts`** from scratch,
preserving only the safe options (aliases, resolve, build settings):

```typescript
// Stage 06: extract safe options from source config, generate clean one
const safeOptions = extractSafeViteOptions(sourceConfig);
const cleanConfig = generateCleanViteConfig(safeOptions);
// base: './', react(), path aliases — nothing else
```

---

### 11. Path Alias Resolution

**Problem:** Many Lovable projects use `@/` as a path alias (e.g. `import { Button } from '@/components/ui/button'`).
The generated `vite.config.ts` doesn't include the alias, so builds fail with "Cannot
resolve '@/...'".

**Fix:** Detect `@/` aliases in source `tsconfig.json` and inject them into the
generated vite config:

```typescript
resolve: {
  alias: {
    '@': path.resolve(__dirname, './src'),  // auto-detected from tsconfig paths
  }
}
```

---

### 12. Better Logging — Structured JSON Log File

**Problem:** All logs currently go to `console.log`. If a conversion fails, there's no
log file to diagnose the issue.

**Fix:** Write a `webtoapp-conversion.log` in the output directory with JSON lines:

```json
{"ts":"2024-01-01T12:00:00Z","level":"info","stage":"05-install","msg":"npm install complete","durationMs":45000}
{"ts":"2024-01-01T12:00:45Z","level":"error","stage":"06-build","msg":"Cannot find module lovable-tagger"}
```

## 🔴 Strategic Improvements — Larger scope

### 13. `webtoapp.config.json` Schema Validation

**Problem:** The config file has no schema validation — typos (e.g. `"mode": "offlin"`)
cause cryptic runtime errors deep in the pipeline.

**Fix:** Add a JSON schema (`webtoapp.config.schema.json`) and validate on startup:

```typescript
import Ajv from 'ajv';
const valid = ajv.validate(schema, config);
if (!valid) throw new Error(`Invalid config: ${ajv.errorsText()}`);
```

This also gives users VS Code autocomplete in their config file via `$schema`.

---

### 14. Watch Mode for Development

**Problem:** During development of the converted app, users have to manually restart
electron after every source change.

**Fix:** Add a `webtoapp dev` command that:
1. Starts Vite in watch mode
2. Starts the local Express backend
3. Launches Electron pointing to `http://localhost:5173`
4. Reloads Electron when Vite rebuilds

---

### 15. Migration Report HTML

**Problem:** After conversion, users don't know what changed, what was skipped, or what
needs manual review.

**Fix:** Generate a `webtoapp-report.html` in the output directory that shows:
- ✅ Every file transformed (with diff)
- ⚠️ Low-confidence transforms (needs review)
- ❌ Files that couldn't be converted
- 📦 Dependency changes
- 🔑 Credentials that were stripped
